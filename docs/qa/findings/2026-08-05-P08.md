### Note — a case made unstable by JC-014, fixed during the run

P08-001 compared a character to its own round trip with the save happening
*between* the two reads. JC-014 added `saved_as` — the storage slot a character
was last written to, which is how it tells "overwriting myself" from
"overwriting someone else" — and `cacheCharacter` stamps it on the way out. So a
character loaded from a fixture, which has never been in a slot, gained exactly
one field across that first save and the case failed. A second run passed.

A regression case that fails once and then passes is worse than one that fails
consistently, so the Check now saves first and compares afterwards. That is also
closer to what the case's title claims to measure. Counted as PASS on the
corrected ordering; the per-key diff across the original comparison was empty
apart from `saved_as`, so nothing else moved.
