### NEW-001 — FAIL
A pool tile's own effect lines contradict the total it prints, for any dose
taken more than once.

`poolTile` (`static/sheet.js:2638`) reads the per-dose value:

    const n = e.pools[pool] || 0;

while `poolEffectMod` (`static/sheet.js:11437`) multiplies by the counted doses:

    n += e.dose ? each * doseTally(e.label).counted : each;

With the fixture's three live Crams, the Focus tile renders:

    ◈ 0 | FOCUS | 14 / 14 | ⚡ Wildling −3 | ⚡ Cram +2 | ⚡ Sixgun +4

7 base − 3 + 2 + 4 = 10, but the tile says 14. 14 is the correct number
(Cram counts three times, +6); the breakdown is what is wrong. The line's own
tooltip makes it worse — it reads *"this is already in the number above"*,
asserting an agreement that does not hold.

The Running Now panel gets the same data right (`Cram ×3 (+6 Focus)`), so the
two surfaces disagree with each other on the same screen.

### NEW-002 — FAIL
Dismissing one dose removes **every** dose when the entries carry no `uid`.

`dismissDose` (`static/sheet.js:11370`) filters on identity:

    CHAR.play.doses = activeDoses().filter(d => d.uid !== uid);

Entries with no `uid` all compare `undefined !== undefined` → false, so a single
`✕` empties the list. Observed while building this fixture: one click on
"Dismiss dose 2 of 3" took all five doses and dropped Focus from 14 to 4.

Not reachable from the app's own UI — `takeDose` has assigned a `uid` since the
feature landed (`a85fa8b`), and `md-import.js` does not restore doses. The route
is hand-edited or externally-generated character JSON, which is exactly what a
fixture is. Worth a guard rather than a rule.

The fixture now ships `uid`s (`qa-dose-1-cram` …), so it exercises the correct
path; this finding records the fragility, not a fixture defect.
